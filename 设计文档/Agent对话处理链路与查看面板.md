# Agent 对话处理链路与前端查看面板

## 目标与流程

用户在 RTC 语音定稿后或手动输入文本后，均调用同一个会话轮次接口。后端依次读取系统提示词、画像、相关长期记忆和短期会话历史；使用子查询 LLM 改写检索问题；通过 Gateway 向量索引检索；若命中含 `parent_id`，读取父块并保留子片命中关系；将这些资料与当前对话组装为回答 LLM 的新请求；并行运行记忆分析 LLM。回答仍以 SSE 流式返回。

## 信息架构与界面位置

沿用主页面已有右侧信息栏。在右侧提供“本轮处理链路”入口，展开后显示最新轮次的阶段时间线。每个阶段可点击展开，查看该步骤的安全摘要、输入/输出概览、状态和耗时。检索结果展示相似度、来源、子片序号与父块标识；点选命中可查看正文及父块上下文。面板同时提供手动文本输入框与发送按钮，可在没有加入 RTC 房间时创建普通 Agent 会话并提问。

## 面板状态

- 空闲：提示可以先输入文本或加入语音房间。
- 处理中：按顺序更新上下文、子查询、向量检索、回答生成、记忆分析阶段。
- 完成：保留该轮步骤与检索结果，允许点击展开。
- 部分失败：展示发生失败的步骤和可读错误；如 RAG 不可用，回答流程按原有降级规则继续。
- 新问题提交：开始新轮次，旧轮次可在本轮列表中重新点开查看。

## 展示与隐私边界

界面展示真实执行事件、检索问题、命中内容与状态，不展示模型隐藏思维链或系统提示词全文。身份标识、API Key 和服务端凭据不进入事件。输入、记忆正文与命中正文仅返回给当前已验证用户的会话浏览器。

## API / SSE 契约

`POST /api/agent/sessions/{session_id}/turns` 继续接收 `{text, turn_id}`。在现有 `text_delta`、`audio_chunk`、`llm_done`、`done`、`error` 事件中增加 `trace` 事件，包含 `stage`、`status`、`occurred_at`、阶段摘要和必要的阶段数据。语音与手动输入都消费同一事件流。手动输入独立复用已鉴权的会话创建 API，不增加平行问答端点。

## 组件边界

- 右侧面板负责输入、展示、阶段展开与命中详情。
- 现有 RTC Hook 继续负责采集语音、ASR 定稿、TTS 播放，并把同一 SSE 轨迹写入可共享状态。
- 前端共享 API 客户端负责创建会话和解析 SSE；不构造 Gateway 请求。
- Agent 编排服务负责各步骤顺序与 trace 回调；知识库适配层负责向量查询及父块展开；LLM 服务负责子查询、回答和记忆提取。

## 适配与验证

现有 Arco 组件与 CSS Modules 作为视觉基础，桌面端使用右侧抽屉承载完整过程，移动端入口以抽屉适配窄屏。实现后进行前后端类型/构建验证，并通过代码路径确认语音与文本走同一 `/turns` SSE 契约；真实 Gateway/LLM 的可用性需在用户环境验证。
