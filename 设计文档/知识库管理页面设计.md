# 知识库虚拟文件管理第一版

## 目标与边界

将知识库中的文件上传和直接文本输入统一为虚拟文件。用户管理目录、名称和内容；后端生成内部 `document_id`，以当前 collection 内的规范化 `directory/name` 作为来源键。相同路径再次写入视为更新，哈希一致且展示 metadata 未变化时跳过嵌入。项目本地仅维护目录项、哈希和切片 ID/序号映射；Gateway 保存切片文本及向量。

本版暂不提供多 collection、文件夹独立创建/移动/批量操作、全文预览和版本历史。目录由文件路径隐式形成。RTC 页面及对话接口保持独立；未来长期记忆可复用“资源目录 + 稳定 ID + 内容哈希 + 向量记录映射”，但不与知识库共用 collection 或数据类型。

## 用户流程

1. 用户登录后进入 `/knowledge-base`，页面读取当前 Gateway collection 状态和项目目录项。
2. 左栏按 `path` 聚合出文件夹；选择目录后，右栏列出该目录下虚拟文件。
3. 用户可以在当前目录粘贴文本并命名，也可以上传 `.txt`/`.md` 文件；上传文件名默认作为虚拟文件名，可编辑目录。
4. 同一路径已存在时，提交前明确显示“将更新此条目”；其他路径创建新条目。`document_id` 由后端生成并隐藏在 UI/API 状态中。
5. 后端计算规范化全文 SHA-256 并切片，逐片调用 Gateway。哈希相同且 metadata 不变时跳过写入；变化时沿用原 ID upsert 切片，再删除多余旧片。
6. 页面刷新后可继续浏览条目、检索预览、删除条目；结果显示目录/名称，不要求用户接触内部 ID。

## 页面结构

```text
知识库状态卡（collection、模型、维度、单片上限）
目录导航卡（根目录、产品、产品/安装 …；点击切换当前目录）
┌────────────────────────────┬───────────────────────────────┐
│ 当前目录虚拟文件编辑        │ 检索测试                      │
│ [上传文件]                 │ 查询、Top K、metadata filter  │
│ 目录 [产品/安装]            │ 命中片段与来源路径             │
│ 名称 [安装指南.md]          │                               │
│ 内容 / 上传状态             │                               │
│ metadata JSON [保存/嵌入]   │                               │
│ 当前目录文件列表            │                               │
│ 名称 | 切片数 | 替换 | 删除 │                               │
```

选择“新建文本”或“上传文件”时，名称和目录组成目标路径。选择已有文件后，更新操作沿用该条目的内部 ID；改名/移动本版不直接覆盖另一条路径，后续可增加显式重命名接口。

## API 契约

- `GET /api/knowledge-base/documents` 返回文档目录项：内部 `document_id`、`path`、`name/title`、来源类型、哈希、同步状态、切片数、更新时间。
- `POST /api/knowledge-base/documents` 与 `/batch` 接受 `directory`、`name`、`source_type`、`title`、`content`、`metadata`；同规范化路径更新，响应返回 `document_id` 和 `action=created|updated|unchanged`。
- `DELETE /api/knowledge-base/documents?document_id=...` 仍用内部 ID 定位，不把 ID 暴露给最终用户。
- Gateway 仅接收项目切分后的切片记录，metadata 至少含 `document_id`、`path`、`chunk_index`、`chunk_count`、`chunk_sha256`、来源和全文哈希。

## 状态与约束

- 加载、空目录、选中目录、保存中、同路径更新确认、保存成功/失败、Gateway 未配置均需有明确状态。
- 路径统一使用 `/` 分隔和 NFC Unicode 规范化；拒绝 `.`、`..` 和名称中的路径分隔符。
- 每个 collection 内路径唯一；文件名大小写按当前数据库精确区分。用户同路径重新提交会更新现有条目。
- 文件名只是路径的一部分；相同内容放在不同路径是两个管理条目。
- 本地仅保存目录/哈希/切片映射；迁移允许旧版本已保存的正文暂时留存。新写入和更新不再把正文落入 PostgreSQL。
- 目录来源键暂时按当前服务唯一配置的 collection 作用域；未来支持多个 collection 时，唯一键需扩展为 `(collection, path)`。
