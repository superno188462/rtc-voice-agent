# 长期记忆与 RAG 向量检索入口

## 目标与用户流程

用户在登录后的知识库管理页输入一个 query，选择检索来源（RAG 知识库或长期记忆），执行后查看 Gateway 返回的向量命中、相似度和 metadata。该页面用于检查向量索引和召回结果，不触发回答 LLM。

## 页面与布局

复用现有 `/knowledge-base` 页面右侧“检索测试”卡片，不新增路由或单独页面。卡片增加来源切换：

```text
检索测试
[RAG 知识库] [长期记忆]
[输入 query................................]
[Top K] [检索]
[metadata JSON（仅 RAG 显示）]

结果卡片：来源标题/记忆类型 | Score
          命中文本
          来源 ID / 路径或记忆范围
          展开 metadata
```

保持当前知识库页的 Arco Design 组件、卡片样式、间距和响应式布局。RAG 模式保留 metadata 精确过滤；长期记忆模式隐藏此过滤器，避免暴露或伪造身份字段。

## 数据边界与接口

- RAG 继续调用 `POST /api/knowledge-base/search`，按本项目已有 collection 搜索；服务端认证后调用 Gateway。
- 长期记忆新增 `POST /api/agent/memories/search`，请求只包含 `query` 和 `top_k`。用户 ID 必须由后端身份中心认证结果获取，前端不得提交用户 ID。
- 长期记忆接口从专用 memory collection 查询，并将命中 ID 与 Context 当前记忆条目核对后返回，避免把已删除或失效记录展示出来。
- 两种来源返回统一展示字段：`id`、`content`、`score`、`metadata`；`title` 或 `scope` 用于来源说明。

## 状态与交互

- 初始：显示来源、query 输入框和 Top K；不自动发起查询。
- 校验：query 必填；Top K 为 1–20 整数；过滤 JSON 仅在 RAG 模式解析。
- 加载：请求中禁用查询按钮，保留已输入内容；来源切换时清空旧结果，避免误认数据来源。
- 成功：显示结果数量；0 条显示“未找到相关记录”。每条结果可展开 metadata。
- 错误：显示后端脱敏错误信息，保留 query 和来源，可再次查询。
- 重复请求：同一页面同一时刻只允许一个检索请求。
- 键盘与窄屏：输入支持 Enter 提交；来源选择可键盘操作；窄屏下结果字段纵向排列，不横向溢出。

## 本次范围

只添加检索入口和长期记忆查询 API，不修改记忆提取、保存策略、RAG 文档管理或 Gateway 项目。结果用于诊断召回，不自动注入当前 Agent 对话。
